- **Версия спецификации:** $1.0$
- **Архитектурный паттерн:** Client-Side SPA / Static Landing + Mandatory BYOK (Bring Your Own Key) + Serverless Lead Webhook
- **Целевая локаль:** г. Ташкент, Узбекистан (`ru-UZ`, валюта расчета — $\text{UZS}$)

## ЧАСТЬ 1. ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ (TECHNICAL SPECIFICATION)

### 1. Архитектура системы (System Architecture)

Система строится по принципу **Zero-Server Token Cost**: весь трафик к языковым моделям идет напрямую из браузера клиента в Google Generative Language API с использованием личного API-ключа пользователя, полученного в Google AI Studio.

```text
[Браузер клиента (Лендинг + UI Чата)]
       │
       ├── 1. Ввод данных регистрации (Имя, Телефон +998, Район Ташкента)
       ├── 2. Ввод и валидация Google AI Studio API Key (AIzaSy...)
       │
       ▼
[Client State & Gate Controller (LocalStorage + Memory State)]
       │
       ├──► (Если ключ валиден) ──► Разблокировка UI чата (Hard Gate Open)
       │                                  │
       │                                  ├──► [Model Router: Gemini 3.5 | 3.6 | 3.8]
       │                                  │          │
       │                                  │          ▼
       │                                  └──► POST https://generativelanguage.googleapis.com/...
       │
       └──► (При подтверждении замера) ──► POST Webhook (Telegram Bot / AmoCRM Ташкент)
```

### 3. Спецификация обязательного шлюза авторизации (Mandatory BYOK Hard Gate)

#### 3.1. Конечный автомат шлюза (State Machine)
1. **`LOCKED` (По умолчанию):**
   - Поверх контейнера чата рендерится блокирующий слой (`#apiGateOverlay` с `backdrop-blur-md`).
   - Поле ввода сообщений `#chatInput` и кнопки быстрых промптов заблокированы или перенаправляют фокус на форму регистрации (`#regName`).
   - Индикатор в шапке сайта показывает статус: `API-ключ не подключен`.
2. **`VALIDATING` (Проверка данных):**
   - Проверяется заполнение обязательных полей:
     - `name`: строка, длина $\ge 2$ символов.
     - `phone`: соответствие формату Узбекистана `^\+998\s?\d{2}\s?\d{3}[-\s]?\d{2}[-\s]?\d{2}$`.
     - `district`: одно из $12$ значений районов г. Ташкента или Ташкентской области.
     - `apiKey`: проверка регулярным выражением `^AIza[0-9A-Za-z\-_]{16,45}$`.
   - Выполняется тестовый запрос (или валидация формата для демо-режима) к API.
3. **`UNLOCKED` (Активный режим):**
   - Слой `#apiGateOverlay` скрывается (`display: none`).
   - В шапке сайта и шапке чата отображается маскированный ключ формата `AIzaSy...XXXX` и активная модель (`Gemini 3.5`, `Gemini 3.6` или `Gemini 3.8`).
   - Инициализируется приветственное сообщение агента с подстановкой имени клиента и его района в Ташкенте.

### 4. Спецификация математического ядра и калькулятора цен

Чтобы исключить галлюцинации языковой модели при расчете стоимости в узбекских сумах ($\text{UZS}$), в клиентском коде и в системном промпте фиксируются единые правила расчета.

#### 4.1. Математическая модель расчета
Для каждого окна $i \in \{1, \dots, n\}$ с шириной $W_i$ (в см) и высотой $H_i$ (в см):

1. Перевод габаритов в метры и вычисление фактической площади:
   $$S_{\text{raw}, i} = \frac{W_i}{100} \times \frac{H_i}{100}$$
2. Применение технологического минимума площади ($S_{\min} = 1.0\text{ м}^2$ на изделие):
   $$S_i = \max\left(1.0,\; S_{\text{raw}, i}\right)$$
3. Суммарная расчетная площадь заказа:
   $$S_{\text{total}} = \sum_{i=1}^{n} S_i$$
4. Стоимость изделий по выбранному тарифу $C_{\text{type}}$ ($\text{UZS/м}^2$):
   $$P_{\text{items}} = S_{\text{total}} \times C_{\text{type}}$$
5. Стоимость монтажа $C_{\text{install}}$:
   $$C_{\text{install}} = \begin{cases} 0\text{ UZS}, & \text{если } n \ge 3 \text{ (акция «Бесплатный монтаж от 3 окон»)} \\ 0.15 \times P_{\text{items}}, & \text{если } n < 3 \text{ и выбран монтаж без акции} \end{cases}$$
6. Итоговая сумма:
   $$P_{\text{total}} = P_{\text{items}} + C_{\text{install}}$$

#### 4.2. Константная таблица тарифов (`PRICE_MATRIX_UZS`)
- `zebra_day_night`: $220\,000\text{ UZS/м}^2$ — Рулонные шторы «День-Ночь» (Зебра, Турция)
- `cassette_blackout`: $280\,000\text{ UZS/м}^2$ — Кассетные шторы Blackout $100\%$ (защита от жары)
- `roll_screen`: $160\,000\text{ UZS/м}^2$ — Рулонные шторы «Светофильтр / Screen»
- `horizontal_alu`: $130\,000\text{ UZS/м}^2$ — Горизонтальные алюминиевые жалюзи
- `vertical_office`: $115\,000\text{ UZS/м}^2$ — Вертикальные тканевые жалюзи
- `plisse_roman`: $310\,000\text{ UZS/м}^2$ — Шторы Плиссе и Римские шторы

### 5. Спецификация интеграции с Google Generative Language API

#### 5.1. Формирование запроса
- **HTTP Метод:** `POST`
- **Endpoint:** `https://generativelanguage.googleapis.com/v1beta/models/{api_model_id}:generateContent?key={user_api_key}`
- **Headers:** `Content-Type: application/json`
- **Payload структура:**
```json
{
  "systemInstruction": {
    "parts": [
      {
        "text": "Системный промпт с переменными: {selectedModel}, {userName}, {userDistrict}, {userPhone} и таблицей цен в UZS"
      }
    ]
  },
  "contents": [
    {
      "role": "user",
      "parts": [{ "text": "Сообщение пользователя" }]
    }
  ],
  "generationConfig": {
    "temperature": 0.5,
    "topP": 0.95,
    "maxOutputTokens": 1024
  }
}
```

#### 5.2. Детерминированный Fallback-движок (Offline / Demo Resilience)
Если пользователь тестирует интерфейс с демонстрационным ключом или возникает сетевая ошибка / исчерпание лимита бесплатного тира (`HTTP 429`), агент автоматически переключается на встроенный локальный парсер регулярных выражений:
- Распознает паттерны размеров `(\d{2,3})\s*[xх*на×]\s*(\d{2,3})` и количество окон `(\d+)\s*(окн|шт|створ)`.
- Вычисляет точную смету по формуле $S_i = \max(1.0, \frac{W}{100} \times \frac{H}{100})$ для трех популярных категорий («День-Ночь», «Blackout $100\%$», «Горизонтальные») и выводит ответ с маркировкой выбранной модели (`Gemini 3.5`, `3.6` или `3.8`).

### 6. Спецификация UI/UX-компонентов лендинга

1. **`TopInfoBar`:** Фиксированная верхняя панель с гео-привязкой к Ташкенту, телефоном `+998 (71) 200-55-77` и динамическим индикатором статуса API-ключа (`#headerAuthBadge`).
2. **`StickyHeader`:** Логотип `JalyuziTashkent.AI`, якорное меню (`#catalog`, `#api-guide`, `#ai-agent`, `#districts`) и кнопка быстрого перехода к подключению ключа.
3. **`HeroSection` + `QuickCalculatorCard`:**
   - Слева: УТП с акцентом на защиту от ташкентского солнца и работу на базе `Gemini 3.5 / 3.6 / 3.8`.
   - Справа: Интерактивный калькулятор с ползунками ширины ($40\text{–}300\text{ см}$) и высоты ($50\text{–}300\text{ см}$), мгновенным пересчетом в $\text{UZS}$ и кнопкой `transferCalcToAI()`, передающей выбранные габариты прямо в чат агента.
4. **`ApiGuideSection` (`#api-guide`):** Визуальный блок из $4$ карточек с прямой ссылкой на `https://aistudio.google.com/app/apikey` и подсветкой формата ключа `AIzaSy...`.
5. **`AgentWorkspaceSection` (`#ai-agent`):** Двухколоночный модуль ($5$ колонок — форма регистрации и управления ключом/моделью; $7$ колонок — окно чата с `Hard Gate` оверлеем, переключателем `3.5 | 3.6 | 3.8 Pro` и чипсами быстрых промптов).
6. **`CatalogSection` (`#catalog`):** Карточки продуктов с кнопкой «Рассчитать с ИИ», запускающей расчет конкретной позиции в чате.
7. **`TashkentDistrictsBanner` (`#districts`):** Блок охвата всех $12$ районов Ташкента для повышения локального доверия и SEO.
